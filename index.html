Architecture Highlights

Engineered following enterprise patterns for high resilience, zero thread blocking, and deterministic failure isolation.

⚡

Event-Driven Decoupling

REST controllers immediately return 202 Accepted upon queuing requests into Kafka. Partitioning by userId guarantees strict sequential processing per user without cluster bottlenecks.

🛡️

Circuit Breaker & Fallback

Guarded by Resilience4j with a 50% failure rate threshold. When tripped to OPEN, downstream calls fail fast without network execution, deferring notifications gracefully.

🐳

One-Command Containerization

Orchestrated via Docker Compose linking Zookeeper, Kafka broker, and the Notification Service on a dedicated bridge network with built-in Actuator healthchecks.

REST API Specifications

Production-ready endpoints for sending notifications, querying in-memory records, and observing Actuator metrics.

POST /api/notifications/send 202 Accepted

Accepts notification requests and asynchronously dispatches them to Apache Kafka.

curl -X POST http://localhost:8080/api/notifications/send \ -H "Content-Type: application/json" \ -d '{ "userId": "alice101", "message": "Your order #4492 has shipped!", "notificationType": "EMAIL" }'
GET /actuator/circuitbreakers 200 OK

Inspects real-time Resilience4j circuit breaker state, buffered calls, and failure rates.

curl http://localhost:8080/actuator/circuitbreakers
POST /mock-users/configure?fail=true 200 OK

Dynamically simulates downstream service outages to demonstrate Circuit Breaker state transitions.

# Trigger failure mode curl -X POST "http://localhost:8080/mock-users/configure?fail=true" # Restore healthy state curl -X POST "http://localhost:8080/mock-users/configure?fail=false"
